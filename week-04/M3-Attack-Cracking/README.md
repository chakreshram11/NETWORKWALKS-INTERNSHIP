# M3 — Attack (Cracking)

## Mediroza General Hospital Web Application Penetration Test

> **Networkwalks — Week 4 | Authorized Security Lab**

### Objective

Milestone 3 required identification of **staff salary information and shareholder details** belonging to Mediroza General Hospital.

The project brief explicitly defines this as the M3 objective. fileciteturn4file0

---

## Discovery

During web content enumeration, the following path was disclosed:

```text
/old/
```

The directory contained a legacy SQL database backup:

```text
mediroza_db_backup_2019.sql
```

The backup was directly accessible from the public web server.

---

## Attack Path

The demonstrated attack chain was:

```text
robots.txt
     │
     ▼
/old/
     │
     ▼
mediroza_db_backup_2019.sql
     │
     ▼
Direct unauthenticated retrieval
     │
     ▼
Database structure + records
     │
     ├── staff
     │    └── salaries / PII
     │
     └── shareholders
          └── ownership information
```

## Security Impact

The vulnerability is significantly more serious than simple directory disclosure because the exposed file contains structured database records.

Potential consequences include:

### Personnel confidentiality

Employee salaries and personal identifiers can be disclosed.

### Corporate confidentiality

Shareholder ownership information is publicly exposed.

### Further compromise

A database backup may contain additional credentials, configuration information or historical application data in other environments.

### Compliance exposure

The disclosure of personnel and healthcare-related information may trigger privacy, security and breach-response obligations depending on the applicable jurisdiction and circumstances.

---

## Risk Rating

**Severity: Critical**

The public database backup provides direct unauthenticated access to sensitive structured data and bypasses normal application-level authorization.

---

## Recommended Remediation

### 1. Remove the exposed backup immediately

Delete:

```text
/old/mediroza_db_backup_2019.sql
```

from the public document root.

### 2. Move backups outside the web root

Backups should never be stored in a directory served by the web server.

Recommended architecture:

```text
Web Server
   │
   ├── public/
   │
   └── [NO DATABASE BACKUPS]

Restricted Backup Storage
   │
   ├── Encryption at rest
   ├── Authentication
   ├── Access control
   └── Audit logging
```

### 3. Disable directory indexing

The web server should not generate directory listings for application directories.

### 4. Scan for other exposed files

Search for:

```text
*.sql
*.sql.gz
*.bak
*.backup
*.zip
*.tar.gz
.env
config.php
database.php
```

### 5. Rotate potentially exposed secrets

If any credentials, API keys or database passwords exist in the exposed backup, rotate them immediately.

### 6. Review historical backups

Identify whether older backups are also publicly accessible.

### 7. Implement deployment controls

CI/CD pipelines should prevent database dumps and secret/configuration files from entering the public web root.
